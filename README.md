# moodboard

A mobile-first, offline-first moodboard builder. Original images, customizable tabs and collapsible sections, and complete portable saves. The published board is publicly viewable; publishing edits requires GitHub repository write access. There are no runtime dependencies or image recompression.

## Save the shared board to GitHub

The published website loads the shared board from this repository's **`board` branch**, not from another device's browser storage. Anyone can browse it, including a phone or incognito browser. Your existing local collection is preserved when connecting: a separate local collection is merged into the shared board, and conflicting versions are reported rather than silently overwritten.

To upload edits:

1. Open **Settings and backups → Enable auto-sync**.
2. Use **Open GitHub sign-in and token setup**, sign in, and create a fine-grained access token restricted to the **moodboard** repository. Grant **Contents: Read and write**; metadata read access is automatic.
3. Paste that token into the masked field in the app, not into chat, and save. This is token authentication to GitHub, not a native OAuth popup.
4. Pasting, uploading, cropping, reordering, editing, and deleting now autosave after a short debounce. Wait for **Saved to GitHub** before expecting a new device to see the change.

The GitHub token is kept **only in the open tab**, sent only to `api.github.com`, and never written to source files, browser storage, JSON backups, or portable HTML. Enter it directly in the masked **Enable auto-sync** dialog. Rejected authentication or reloading clears it. No credential is prefilled or hard-coded into the website. Revoke any exposed token in GitHub settings. Reconnect after reloading to upload further edits. Public viewing never needs the token. There is **no separate save server, tunnel, or cloud storage account**.

The editable **Coupon code** box at the very bottom of settings, below Accent color, starts with the public coupon `l33thelper`. **Copy coupon** copies the current input; the floppy-disk **Save coupon** icon saves it with the board. With auto-sync enabled, the saved coupon uploads to GitHub and appears on other devices. Offline changes wait to sync, and JSON backups and portable HTML include the saved value. Both icons are 20px. The coupon is public and never used for authentication; GitHub access tokens are rejected in this field.

Original files are committed under `images/`, with the original filename retained in the path and board metadata. `board.json` stores tabs, sections, titles, notes, source URLs, and nondestructive crop coordinates. Copies share their original file; deleting its last placement removes the current Git file. **Git history still retains earlier copies.** The separate data branch avoids rebuilding GitHub Pages for every pasted image.

Offline changes are saved in IndexedDB with a persistent outbox. Reconnect to the internet and choose **Enable auto-sync** to upload them. Independent edits merge automatically using the last acknowledged shared state and stable tab/section/image IDs. Layout changes, deleting still-empty tabs, and importing images elsewhere do not conflict or duplicate placements. Locally changed display preferences win concurrent display changes. Readers with pending local edits still receive subsequent imports without enabling uploads. Older clients recover their baseline from Git history. Competing edits to the same content, incompatible reorders, or deleting a tab that gained images remain visible conflicts, protecting both versions. Export a backup before using the manual **Merge local with Github version** (which may duplicate placements), **Replace local with Github version**, or **Replace Github with local version**. Load/replace actions require confirmation where they would discard edits.

Fresh public visits resolve the latest Git commit through GitHub's API, then install validated organization immediately and show originals from that **same immutable commit**, avoiding stale branch-file caches and mixed versions. New visitors start on the first nonempty tab if the saved active tab is empty. Full originals cache in the background with four concurrent downloads, checksum/signature/dimension checks, and visible progress; already verified local originals are reused. **Offline ready** appears only after all originals are durably cached and the app shell is installed. Failed caching is reported explicitly; online previews are not a complete offline backup. JSON/portable exports fetch and verify every uncached original before producing any download, never a success-shaped partial backup. Organization-only uploads reuse immutable original records instead of downloading/base64-packaging the collection; only new or restored files need upload bodies. Public pages recheck approximately every five minutes while visible (or when returning after a minute); connected editors recheck more frequently. **Force re-sync** refreshes the shared version and retries original caching. Concurrent upload races retry against the latest revision without overwriting another save. GitHub's anonymous/authenticated API rate limits and 100 MiB individual-file limit apply; failed uploads remain local. Image bytes are never reduced to work around those limits.

Large exports are assembled one original at a time into Blob parts, avoiding the browser's single-string limit. Portable HTML remains one standalone file, with separately embedded original records decoded incrementally on opening; older portable files remain supported. JSON backups over 128 MiB of originals (or exported before caching finishes) use streaming **JSON Lines (`.jsonl`)**, containing a metadata header and one original per line. Import accepts both `.json` and `.jsonl`, verifies the record count and every image before replacing anything, and rejects truncated files. Background downloads stay concurrent but full-resolution decoding is serialized to limit peak pixel memory on phones. These formats preserve every original byte, but very large collections still require sufficient browser storage, RAM and disk space.

## Start locally

Open `index.html` directly in a desktop browser. It contains the entire app.

For an installable offline web app, use Node.js:

```powershell
npm start
```

Open http://localhost:8085. Wait for **Offline ready**. HTTPS hosting or localhost is required for service workers, installation, and the clipboard read button. Keyboard pasting works wherever the browser permits clipboard events; a file picker is always available.

## Collect and organize

- **Paste:** Ctrl+V / Command+V outside a text field. The paste toolbar and its former menu shortcuts are hidden. Pasted clipboard bytes and uploaded image files are stored without resizing or recompression.
- **Source pages:** pasting also saves the original page link when the clipboard explicitly provides it (a `SourceURL` header, canonical URL, or Open Graph page URL in its HTML). This works with keyboard paste and the Paste button when those formats are available. An image's `src` or an arbitrary surrounding hyperlink is not assumed to be the page address. Browsers frequently omit page metadata, and screenshots normally contain none. Add or correct **Source page URL** in the image's **···** details menu; open saved links using **Source page** in the viewer. Links survive copies, moves, offline HTML exports, and JSON backups. Visiting the source website still requires internet; it is not downloaded.
- **Placement:** click a **Paste here** gap before an image, or the end of a section to append. An empty section contains one large **Add or paste at the end** target instead of a decorative placeholder; clicking it selects that section for subsequent pastes/uploads, and it also accepts dropped image files. Change that location anytime. Consecutive pastes keep their incoming order. **Add a section** spans the full board width. The board/footer omit decorative filler text while retaining the offline guide and readiness status.
- **Upload:** upload buttons are hidden by default, including older boards without a preference. Enable **Settings and backups → Show Add image buttons**, beside the caption switches, to reveal the header and matching 20px section upload icons. The section checkbox appears before upload, followed by **···**. The preference is shared and included in backups/portable copies. Paste targets and file drag-and-drop remain available when buttons are hidden. Multiple files are accepted together.
- **Browse:** click/tap an image to open its original-resolution, edge-to-edge viewer (no left/right padding). Use arrow keys, previous/next buttons, or horizontal swipes. **Actual size** allows panning. **Open original** opens the actual source image URL when recorded, separately from the source webpage; otherwise it opens the saved original blob. Clipboard HTML's unambiguous HTTP(S) image `src` is saved when available; missing URLs are never invented. The download button always uses the saved original, including offline. External source links need internet.
- **Select:** Grid and List always show checkboxes while editing. Masonry shows them on desktop hover, keyboard focus, and selected images; touch devices always show them. Checkboxes are 30% smaller, with larger touch/click targets. Use Ctrl/Command-click, Shift-click range, Ctrl/Command+A, or quickly drag a desktop selection rectangle from an image, checkbox, or blank space. Hold Ctrl/Command/Shift while dragging to add to the selection; Escape cancels a selection drag. The bottom toolbar has **All** plus icons for selecting the sections containing already-selected images, copy, move, delete, and clear. Section selection includes every represented section, not unrelated sections or tabs.
- **Crop:** each image has an icon-only crop button. The compact editor is titled **Crop image** without the filename or numeric fields and always loads the full original. Drag on the original to draw a crop, drag inside the frame to move it, or resize with the four corners. Focus the frame and use arrows to move, or Shift+arrows to resize in one-percent steps. **Reset crop**, **Cancel**, and **Save** share the bottom bar. Reset restores the full view; Cancel discards editor changes. Crops affect the board view in all layouts, not the original-resolution viewer or downloads. Only crop coordinates are saved: originals are never modified or recompressed. Crops survive copies, moves, reloads, JSON backups, and portable HTML saves, including offline use.
- **Rearrange:** hold an image, or hold its dotted grip, then drag. Selected groups retain their relative order. On mobile the grip prevents scrolling during the drag. Drop before/after images, on insertion gaps, or into a section. Hover another tab while dragging to switch tabs. **Move to…** and numeric positions work without dragging.
- **Delete one image:** use the card's **×** button between its move grip and **···** menu, then confirm. Card editing controls are hidden when Edit is off.
- **Delete warnings:** the confirmation dialog lets you enter how many future delete clicks should skip the warning. Entering 10 skips the next 10 successful delete actions after the current confirmation; deleting 10 selected images counts as one action. Canceling or a failed save does not consume/grant skips. Zero warns every time. The allowance is per open tab and resets on reload; it is not shared or included in exports.
- **Tabs:** the reorder button immediately after the tab **+** opens a drag-and-drop order dialog for mouse/touch. Handles also support **Up/Down** and **Home/End**; **Save** applies and syncs the draft order, **Cancel** discards it, and Escape/pointer cancellation cancels an active drag. Active tabs and original assets are preserved. With editing on, double-click a tab to rename, reposition, duplicate, or delete it. Keyboard users can focus a tab and press **F2**; touch users can press and hold it. A single click still switches tabs. Long section headers use single-line ellipsis instead of wrapping; their full names remain in tooltips and editors.
- **Sections:** use their **···** menus to rename, reposition, duplicate, move sections between tabs, and delete. The checkbox beside **···** selects whole sections for bulk copy, move, or delete; copy/move asks for a destination tab and position. Copies keep independent organization and share originals. Deleting a section deletes its placements and frees an original only when no section or tab still uses it. Section deletion shares the image-deletion warning allowance. Only the title or chevron collapses a section; the count, checkbox, and blank header space do not. Edit controls retain their header footprint when hidden, without extra padding or vertical shifts.
- **Layouts:** icon-only Masonry, Grid, and List buttons have accessible names and tooltips. Masonry fills the horizontal space first, then places subsequent images in the shortest column. Grid stretches occupied columns to use the available width. The unlabeled display-size slider changes only thumbnails, never source image dimensions.
- **Spacing:** enter an exact whole pixel value from 0 to 40 in the **px** field beside the image-size slider, then press Enter or leave the field. This changes actual card gaps in every layout. The setting is saved with the board, shared through GitHub, and included in offline exports. Selection rectangles can start in the outer board padding or between images; clicking a gap still sets the paste position.
- **Section organization:** the icon-only **Collapse all sections** control collapses the current tab's sections. Drag a section's dotted header grip to reorder it; sections temporarily compact during a drag and retain their saved collapsed/expanded states afterward. Escape/touch cancellation restores the original order. Focus a grip and use Up/Down or Home/End for keyboard reordering.
- **Details ordering:** tab and section dialogs have a collapsed **Rearrange** control directly below Position. Expand it to drag entries or reorder with keyboard handles; the edited entry is bold. Position and the dragged order stay in sync, and Save/Cancel applies/discards the entire order. Changing a section's destination tab updates that tab's reorder list.
- **Lightbox:** square icon buttons show a globe for the source webpage, an outward arrow for Open original, and expand/contract corners for Actual size/Fit image. Globe icons are also used on cards and in photo details. The list icon immediately before Download toggles **Other sections**: every other section sharing that original (once per section), formatted as **Tab > Section** in 30% smaller text. Choose one to jump directly to it, including another tab or a collapsed section.
- **Paste at the end:** sections with images have a slim paste gap below the last image, matching the gaps above photos. Empty sections retain their larger add/paste target.
- **Shy header:** the top header is at most 50px tall, with **Enable auto-sync** kept on one line. The tabs and layout/edit rows are each 50px tall. All three stick together while browsing, hide when scrolling down, and return when scrolling up or focusing a header control. Keyboard focus and active drag/editor/viewer interactions keep the controls accessible.
- **Card captions:** **Settings and backups → Caption** has a compact switch beside the Caption heading for the entire caption, plus inline filename and URL switches. **Save** and **Cancel** sit directly beneath these controls. Captions are off by default, including older backups without a caption preference; explicitly saved preferences are preserved. Turning captions on initially shows URLs, not filenames. Missing source URLs have no placeholder text or empty caption space. Original filenames are retained on import, including files collected from blog entries. Notes and file sizes remain hidden in caption markup and available in the details editor/viewer. Each image's 30px editing/link buttons overlay the picture's bottom-right corner in every layout, without reserving caption space.
- **Source shortcut:** images with a saved page URL have an icon-only link beside their hover controls and in their **···** details menu. It opens the original webpage in a separate tab, independently of caption visibility. Images without a source URL do not have a fake or disabled link.
- **Photo details:** fields are ordered Source page URL, Section, Position, Notes, Filename, then original-file metadata and action buttons. A 20px **Go to site** icon sits beside the source URL label and follows edits to that URL. The selection bar uses 30px buttons with 20px icons, a folder-and-arrow Move icon, and Clear selection beside the count. Copies create independent placements/crops while sharing one original asset, including in GitHub and portable exports.
- **Header and settings:** the hamburger, page icon, and upload buttons are on the left, with save status before Download on the right; there is no logo or tagline. **Manage** starts with Login / Enable auto-sync and Force re-sync. Backup export/import share a row, followed by Protect browser storage directly above Merge local with Github version; the guide is last. The info icon toggles descriptions directly underneath each management button, not in a separate help section. It is filled when enabled, works offline, and does not close settings. Login is hidden once this tab is connected, and Disconnect GitHub is hidden. **Enable auto-sync** authorizes the app using the token flow and displays a checkmark without changing button size; a GitHub website session alone is not an app connection. Text mentions of **Enable auto-sync**, including the save-status prompt, link to that authorization dialog. Connected edits sync automatically; Force re-sync retries/refreshes manually. GitHub controls remain visible when unavailable: internet-dependent actions are greyed out offline and sync actions are disabled in local/portable copies, with explanatory tooltips. Local editing, backups, and portable export remain usable offline. Conflict warnings appear at the top of Manage. **Last sync** shows the local date and time of this device's last successful GitHub read or upload, retained across reloads in browser metadata; offline edits, failed requests, and unresolved conflicts do not advance it. **Destructive actions** separately lists replacing GitHub with the local version and replacing the local version with GitHub. Caption switches and their Save/Cancel controls follow Manage; accent color remains at the bottom. Protect browser storage requests protection from automatic eviction, not from clearing site data or losing the device. An existing collection's theme is preserved.
- **Edit mode:** starts on each time the app opens. Use the horizontally flipped pencil beside the layout icons to toggle it. Its button is a 38px square; control icons are 20px square, with their larger touch/click targets preserved. Turning it off hides editing controls and prevents accidental edits while browsing. The intro and paste toolbar are hidden; the header image-plus icon uploads images and **+ Add a section** remains at the bottom.

PNG, JPEG, GIF, WebP, AVIF, BMP, and ICO raster images are supported when the browser can decode them. SVG and unrecognized image formats are rejected explicitly. Screenshots preserve the clipboard's bytes and dimensions, which may differ from the source image copied by another application.

## Take it offline on a computer or USB

The separate [Hanfu moodboard](./hanfu-moodboard.html) is a self-contained, memory-only HTML file (about 40 MB). It contains Hanfu pose / All and Hanfu sword / Full / Small, with 39 unique original images shared across 79 placements. It does not add those images to the shared board or its IndexedDB cache. Download it for offline use; save a new portable copy after editing.

Use **Export** in the header to create a smaller independent HTML board. Choose individual sections, use each tab's checkbox to select/deselect all its sections, or select everything. The dialog shows selected tab, section, and unique-original counts. Only referenced originals are embedded, once per asset, without resizing or recompression. The export gets a new collection identity, so reopening it cannot substitute autosaved edits from the full board. Your current board and its pending edits are unchanged. **Download** includes the entire board.

Downloaded HTML does not need the hosted site's service-worker cache, but opening/editing it still uses browser memory and, when available, IndexedDB. A very large file can exceed those limits too. The original downloaded file keeps its embedded images; edits are not written back into that file automatically. Save a new portable copy after editing, and keep separate backups. Smaller selected exports reduce both file size and per-board resource needs.

Dedicated memory-only portable files explicitly set `{"memoryOnly":true}` in their `portable-options` payload. They never open IndexedDB, register a service worker, send cross-window change messages, or enable GitHub sync, even when served on the published origin. Saving full or selected HTML copies preserves this mode. Images still consume RAM while open, and edits are lost unless you save a new copy before closing. A different filename alone does not guarantee browser-storage isolation.

The **Export** dialog includes **Memory-only file (no browser autosave)** so you can make smaller travel copies without an image database. If a normal portable copy cannot stage, read, or save browser storage, it falls back to its fully validated embedded snapshot with an explicit warning, rather than disabling the board. Stored browser-only edits may be newer than that snapshot; they are not overwritten by recovery. Malformed/incomplete embedded files still fail validation. Keep untouched backups, test each travel file in airplane mode on the destination device, and save a new HTML after organizing it.

To transfer original files without clipboard permission, select photos (or whole sections) and use **Download selected originals**, the download-arrow icon in the selection bar. It downloads one uncompressed ZIP containing each selected original asset once, without applying crops, resizing, or re-encoding. Extract the ZIP, choose a paste location in the destination board, and drag/drop the extracted images there (or use its image picker). Files retain their filenames unless unsafe characters or duplicate names require safe suffixes. Notes, crops, and section organization are not part of this raw-file transfer; importing into the destination uses that board's storage. ZIP downloads are limited to 4 GB and 65,535 files; split larger selections.

**Copy with photo metadata:** select images or whole sections, then use **Copy** or Ctrl+C / Command+C. Wait for **Copied**, open another updated moodboard HTML, choose a paste gap, and use Ctrl+V / Command+V or **Paste**. The clipboard contains the full original bytes (one per asset), filename, title, notes, source-page URL, source-image URL, and crop. Paste verifies original checksums and image validity before changing the destination; matching known original hashes reuse storage. Source organization and destination display settings are not overwritten. **Copy to another section**, the separate folder-arrow button, retains the within-board destination dialog.

Cross-file clipboard transfers require both files to contain this feature. Browser permissions, local-file clipboard support, and clipboard size limits vary; failures are shown rather than silently pasting thumbnails or dropping metadata. The original-file ZIP remains available when clipboard access is blocked, but raw-file drag/drop does not carry notes or source-page links. Re-export older HTML files from the updated app to include the new clipboard behavior.

The header's **page icon (Separate HTML files)** opens the board library: the main board, Hanfu, three Kyoto campaign files, and two Hanashizuku campaign files. Each title shares a row with its **Open** / **Download** buttons. **Open** on the hosted site opens a lightweight browser-viewable campaign page; full-resolution originals load lazily from immutable GitHub URLs. These online pages need internet, use no IndexedDB or service worker, and do not autosave or sync edits. Browser HTTP caching and RAM still apply. Their header **Download** fetches and verifies every original before creating a complete offline HTML; incomplete downloads fail explicitly. The page-icon **Download** links fetch the already-built full-original HTMLs from [GitHub Releases](https://github.com/wendyyuanlu/moodboard/releases/tag/campaign-boards-v1). Download these before traveling. Sections remain together and in order; splits are balanced by original bytes, with originals deduplicated inside each file. Published standalone downloads are memory-only and do not preload when the library opens. Keep them beside one another with their published filenames for the local dialog's **Open** links to work offline.

Browser-viewable campaign pages:
- Kyoto: [Part 1](https://wendyyuanlu.github.io/moodboard/campaign-kyoto-1.html), [Part 2](https://wendyyuanlu.github.io/moodboard/campaign-kyoto-2.html), [Part 3](https://wendyyuanlu.github.io/moodboard/campaign-kyoto-3.html).
- Hanashizuku: [Part 1](https://wendyyuanlu.github.io/moodboard/campaign-hanashizuku-1.html), [Part 2](https://wendyyuanlu.github.io/moodboard/campaign-hanashizuku-2.html).

`campaign-pages.json` holds only campaign state and immutable original references. The normal build generates the five hosted campaign pages from the shared template alongside the main page. Never embed full campaign originals into these hosted outputs; the independent full-original Release downloads remain the offline versions.

Layout, UI, and other non-image-content changes must be applied to the shared template and every maintained standalone HTML, including the Hanfu page and all five campaign release files, without replacing their images or photo metadata. Previously downloaded or user-edited copies cannot update automatically; re-export them from an updated app when needed. After verified campaign publication, the shared main board no longer contains the campaign tabs or their exclusively referenced original files; originals still referenced by another main-board tab must remain. Older exports and other browser collections retain their own images until separately removed.

1. Add your images and organize the board.
2. Click **Download**. This downloads `moodboard-YYYY-MM-DD.html`.
3. Copy that HTML file to your computer or USB. It contains the entire app and **every full original image from every tab and section, including collapsed sections**, plus filenames, notes, source URLs, crop coordinates, and organization. It does not rely on GitHub image links or thumbnails. No companion folder is required.
4. Open it in a desktop browser without internet.
5. After editing, use **Download** again and keep the latest download. The original file on disk/USB is a snapshot and is **not automatically overwritten**.

Also keep a **JSON backup** from **Settings and backups**. Portable HTML works with no internet, no GitHub login, and even without IndexedDB when the browser permits running local HTML; in that case edits remain in memory until you export again. Portable copies deliberately have online sync disabled and contain no authentication token. A portable file can be large because it embeds originals as base64. Export requires device memory proportional to the collection. Browser storage, file decoding, available memory, and GitHub's file/API limits set practical limits.

## Use it offline on a phone

1. While online, open the HTTPS website in the phone's browser.
2. Use **Add to Home Screen** / **Install app**, if offered.
3. Let the shared GitHub board finish loading all originals. If you are using a separate, unshared local collection, transfer and import its JSON backup instead.
4. Wait for **Offline ready** and test launching/browsing in airplane mode before travelling.
5. For shared edits, choose **Enable auto-sync** on the phone and wait for **Saved to GitHub** when online. Also export a new JSON backup after editing.

Mobile file managers sometimes only preview HTML files and do not execute their JavaScript. Opening portable HTML directly from Files/USB is therefore not a reliable phone installation strategy. Hosted installation plus JSON import is recommended. Phone clipboard APIs differ; use the photo/file picker if image paste is unavailable. Pinch zoom/panning is available through the browser; the built-in viewer provides original-size panning.

## Bring offline changes back to the website

The hosted shared app syncs through GitHub after you connect it. A portable USB file is intentionally an independent snapshot with no credentials or automatic publishing. To bring its edits back:

1. In the offline copy, open **Settings and backups → Export JSON backup**.
2. Open the hosted website on your target device.
3. Choose **Import JSON backup** and select that file.
4. Confirm replacement of the open collection and shared board. Export the previous collection first if you want to keep it.
5. Choose **Enable auto-sync** and wait for **Saved to GitHub**.

USB-to-site transfer is manual; connected edits on the hosted site autosave to GitHub. GitHub Pages serves the static app, and the app uses GitHub's APIs directly for authenticated commits. **The published board and its images are public.** Do not publish private images or commit credentials. Only people with repository write access can publish edits.

## Storage and safety

- IndexedDB caches complete original image blobs, metadata, and the pending GitHub outbox on the current device/origin. Originals have separate records: changing spacing, moving sections, or deleting tabs only saves organization, not the entire image library. Existing caches migrate without redownloading originals. Unsynced edits still exist only on that device. Portable embedded images also work without IndexedDB, with a visible warning and export requirement.
- Closed database connections reopen automatically, with one bounded retry that retains stale-window revision checks. Background original caching reserves 64 MiB for edits and pauses visibly when browser storage is low; already cached originals and online browsing remain usable. Free space and use **Force re-sync** to resume. Real device/browser limits cannot be overridden; wait for **Offline ready** before relying on a complete offline library.
- Large backup/portable imports stage originals in batches without replacing the active board before validation. Temporary import records are removed after success, cancellation, or validation failure.
- Storage failures and stale edits from a second window are reported rather than silently overwriting data.
- A portable copy reopens newer autosaved edits for the same collection in that browser; embedded content is the fallback on a fresh browser/device.
- Deletions require confirmation. Backups/imports are validated before replacement.
- Clearing site data, browser eviction, or private browsing can remove local edits. Export backups regularly. **Protect browser storage** requests persistence but is not a backup.
- No analytics or runtime third-party scripts/fonts. The hosted shared app contacts `raw.githubusercontent.com` to read originals and `api.github.com` for authenticated reads/writes. Ordinary source-page links are not fetched until opened. Portable HTML makes no network requests.

## Develop and test

Requires Node.js. The committed `index.html` inlines `shell.html`, `styles.css`, `board-format.js`, `github-store.js`, `app.js`, and the public repository configuration from `cloud-config.json`:

```powershell
npm ci
npm run check
npm run test:sync
npm run build
npm test
```

Tests use Playwright and an installed Chrome browser, including mobile touch emulation, original-byte checks, portable file reopening, offline reloads, and stale-window protection. Test dependencies are not used by the app.

## GitHub Pages

Publish this folder in a separate `moodboard` repository. In **Settings → Pages**, select deployment from `main`, root directory. Update `cloud-config.json` with the public site URL, repository owner/name, and data branch; never put a token there. Shared sync is enabled only on that configured site, not local previews or USB exports. All paths work at `https://YOUR-USERNAME.github.io/moodboard/`. Increment the cache version in `sw.js` when publishing app updates.
